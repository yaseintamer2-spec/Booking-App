# PROJECT MASTER PROMPT — PREMIUM FOOTBALL MATCH BOOKING PLATFORM (RIYADH, SAUDI ARABIA)

## 1. PROJECT OVERVIEW

Build a complete, premium, production-ready football match booking platform focused exclusively on Riyadh, Saudi Arabia, at launch.

The platform is inspired by the general concept of Wady Le3b, but must have its own original branding, identity, user experience, design system, features and implementation.

This is NOT simply a football pitch booking website.

It is a complete football community and match-organizing platform where users can:

- Discover and join organized football matches.
- Book individual spots in 7v7 matches.
- Pay directly through the application.
- Receive booking confirmations.
- Cancel bookings under a structured cancellation policy.
- Receive eligible refunds into their in-app wallet.
- View their football statistics and match history.
- Compete on player leaderboards.
- Track their goals, assists and achievements.

The platform must also include a dedicated referee interface and a comprehensive administration dashboard.

**The user interface and user experience are the highest priority.**

I want an exceptionally polished application that looks like a professionally designed, funded sports technology startup, not a generic AI-generated website.

Do not compromise the visual quality to save development time.

---

# 2. DEVELOPMENT APPROACH

Use Replit to build the application.

Build it as a mobile-first, responsive Progressive Web App (PWA), with an app-like experience on mobile devices and a fully responsive desktop experience.

The architecture must support:

1. Player application.
2. Referee application.
3. Admin dashboard.
4. Backend and database.
5. Payment processing.
6. Notification system.

These should be different interfaces connected to one backend and one database.

Use a modern, maintainable technology stack.

Preferred stack:

- Frontend: React + TypeScript.
- Styling: Tailwind CSS.
- UI components: Custom components, using shadcn/ui where appropriate.
- Icons: Lucide React, supplemented with imported Figma assets.
- Animations: Framer Motion.
- Backend: Node.js with TypeScript.
- Database: Supabase PostgreSQL.
- Authentication: Supabase Auth.
- Storage: Supabase Storage.
- Server-side business logic: Secure backend APIs and database functions.
- Maps: Google Maps or another suitable mapping provider.
- Notifications: Push notifications and email/SMS integration where configured.

If Replit recommends an alternative that materially improves reliability, explain why before changing the architecture.

Do not build the application as a collection of static mockup screens.

Every major button, form, navigation item, booking action and dashboard interaction must work.

# 9. CANCELLATION AND REFUND SYSTEM

This is a core business feature.

Implement the following proposed policy.

All times must be calculated using the match's local Riyadh kickoff time.

### Scenario 1: Cancellation more than 24 hours before kickoff

If the player cancels more than 24 hours before the match:

- Cancel the booking.
- Release the spot.
- Issue a 100% refund.
- Refund the payment according to the disclosed refund policy.
- Record the transaction.

### Scenario 2: Cancellation within 24 hours

If a player cancels within 24 hours:

- The player submits a cancellation request.
- The system marks the spot as available.
- The system attempts to find a replacement player.
- The replacement must make a successful payment.
- Once the replacement payment is verified, the original player's wallet receives 50% of the original booking price.
- The platform retains the other 50% of the original booking price.

Example:

Original booking: 30 SAR.

Replacement booking: 30 SAR.

Original player receives: 15 SAR in their wallet.

Platform retains: 15 SAR from the original booking.

The replacement player receives the vacant match spot.

### Scenario 3: No replacement

If no replacement player is found before the match:

- Apply the disclosed cancellation policy.
- Do not issue the conditional 50% wallet credit.
- Show the cancellation outcome clearly to the player.

### Important system requirements

- Never credit a refund twice.
- Never issue a late-cancellation wallet credit before replacement payment is confirmed.
- Prevent multiple players from occupying the same spot.
- Maintain transaction history.
- Keep audit records.
- Allow administrators to review disputed cancellations.
- Support match cancellation by the platform with an appropriate full-refund process.

The 24-hour policy must be clearly displayed before checkout and in the cancellation interface.

Make the cancellation rules configurable through the admin dashboard.

Implement the system so it can be reviewed and adjusted to comply with applicable Saudi consumer-protection, e-commerce and payment regulations before launch.

Do not automatically treat wallet-only refunds as legally sufficient without confirming the applicable requirements.
