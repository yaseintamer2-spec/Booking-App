# Booking-App

## Match alerts and staff check-in

Apply `artifacts/lib/db/migrations/0001_match_registrations.sql` and then `artifacts/lib/db/migrations/0002_match_image_gallery.sql` to the app database before deploying the API. Admins can set the venue, neighborhood, street address, Riyadh date/time, and up to three gallery photos when creating or editing a match. Photos are compressed on the device and stored in the match row as image data; a dedicated object-storage/CDN provider is not configured yet. Match cards swipe between photos and auto-advance every five seconds. The check-in QR is available before the match and expires at `startsAt + durationMinutes`; scanners also check the current match end time so an admin schedule change cannot extend an old QR beyond the new end. Set `MATCH_STAFF_EMAILS` on the API to a comma-separated list of verified referee and staff emails; administrators already on `ADMIN_EMAILS` can also use the scanner. Staff open **Profile → Staff check-in scanner** or use the admin console link.

For push alerts, set `EXPO_PUBLIC_EAS_PROJECT_ID` for the mobile build and configure iOS APNs and Android FCM credentials in the Expo/EAS project. Build and install a development or production app (Expo Go does not support remote push notifications on Android). Players opt in from **My Matches → Enable match alerts**. The API stores Expo push tokens and sends waitlist-offer alerts through the Expo Push Service; in-app alerts remain available if push delivery is unavailable. `EXPO_ACCESS_TOKEN` can be set on the API to authenticate Expo Push Service requests.

On first launch, the app requires foreground location permission and a location fix before it routes players to sign-in. Push notifications remain optional. The current location coordinates are kept on the device; this version does not send them to the API.
